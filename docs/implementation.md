# 订阅系统实施记录

## 范围与设计

依据用户提供的 Daily Brief Radar v1.0 技术规格，先完成第一阶段数据模型、支付宝方案 A 订单匹配、内容快照及 Resend 发送，再制作网页入口。用户已授权按规格持续实施，在当前会话内直接执行。

沿用 Python，在现有仓库的新分支开发。SQLite 适合早期规模，所有服务必须共用持久文件。订单核验和有效期变更在同一写事务内完成。业务时间保存为 UTC，日期按罗马时区解释。

采用数据库 outbox 作为初期队列，发送载荷与幂等键持久保存。Resend 幂等键有效期 24 小时，首次尝试超过 23 小时的未确认任务转人工核实，避免跨窗口重发。发送记录中的 success 表示服务商接受请求，最终邮箱送达需要服务商事件确认。

每日快照保存板块内容并禁止覆盖。订阅版生成器采用通用画像，复用已有采集、摘要及来源，个人版入口继续可用。支付通知需校验签名、应用、收款方、金额、交易状态和唯一流水。

## 验证方法

使用 unittest、临时 SQLite 和本地 HTTP 测试服务。支付宝使用临时 RSA 密钥生成并验证真实签名。Resend 的外部 HTTP 边界使用本地替身，持久状态、渲染和队列使用真实实现。真实邮件与收款需要用户的域名、商户及 API 配置。
